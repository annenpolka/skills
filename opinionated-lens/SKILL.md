# Opinionated Lens

## What This Is

opinionatedな議論を共著するための**レキシコン**——共通語彙集。

このスキルは品質保証装置ではない。制約を書いても自律的には守れないことが実証済みだ。このスキルが提供するのは、**問題に名前をつけ、問題を一語で指摘可能にし、対話の速度を上げる**認知的インフラ。

「宣言が広すぎて論証がカバーしてない領域がある気がする」は10語かかる。「Scope Smuggling」は1語。名前があるから修正が速い。名前がなければ踏んだことにすら気づかない。

最初の出力は素描。ユーザーとの対話で研ぐ。レキシコンはその対話を効率化する道具。

## Core Vocabulary（良い出力の語彙）

### Dwelling（滞留）

対象の中に、構造化の意図なしに留まる段階。「何を主張するか」ではなく「これは何か」を問う。宣言の前に来る。種はここで見つかる。

「Smalltalkについて書いて」→ すぐ宣言を作る → 平均的な主張に着地。
「RubyのようにGoを書く」→ 跳躍の中で「社交性」が浮上 → 好奇心 → 滞留 → 記事。

滞留は効率的ではない。しかし滞留なしに書かれた文章は対象の表面しか触っていない。対象を理解する前に対象を切りにいくと、切り口が浅い。

**判定:** この対象について、書き始める前に驚いたことが1つ以上あるか。なければ滞留が足りない。

### Lens（レンズ）

出力の本体。既存の議論を新しい軸で切り直す診断ツール。攻撃は一つのポジションを壊すが、レンズは読者の認知装置を書き換える——以後あらゆる類似場面でレンズが発動する。攻撃はレンズの適用であり、レンズが本体。

レンズの実体は**命名**だ。読者が既に体験しているが言語化できていなかった現象に、初めて名前をつける。「降下深度」を知らない読者も、哲学と実装が乖離する体験は知っている。記事が渡したのは体験ではなく語彙。語彙が体験に貼りつき、以後その体験が語彙を自動的に呼び出す。これがレンズの装着。

良いレンズの性質:

- **新しい軸。** 既存の議論にない切り口。段階的スケールは軸を精密にする手段の一つだが必須ではない
- **可搬性。** 読者が著者なしで、本文外の事例にも適用できる
- **opinionatedness。** 中立な分類ではなく特定の見方を推奨する
- **命名。** 本文中に読者が持ち帰れる1-3個の名前がある。各名前は、既存語彙では10語かかった現象を1-3語に圧縮している。読者がその名前を知らない友人に30秒で説明できるなら圧縮に成功。説明に本文の全文脈が必要なら命名ではなく専門用語

### Stake（賭け金）

宣言に結びつく検証可能な帰結。「正しいなら→[検証可能な帰結]」「間違いなら→[検証可能な反帰結]」。「みんなが困る」は賭け金ではない。賭け金がない主張はopinionatedではなく、ただの感想。

### Position Declaration（宣言）

レンズを一文に圧縮したもの。反射テスト（反論衝動を起こすか）と紋切り型検査（「ああ、その話ね」で済まないか）の両方を通過する必要がある。宣言だけでなく、宣言から着地への論証経路も紋切り型でないこと。

着地でさらに鋭くできる余白（Landing Headroom）を残す——宣言で全弾を撃つと着地で弾がない。

### Landing（着地）

議論全体を一文に圧縮したもの。宣言より具体的な像を持つ。抽象→具象の落差が鋭角度を生む。身体感覚を伴う像に落とす。鈍角の着地は敗北。

**矛盾圧縮:** 記憶に残る着地は「AはXであると同時にnotXである」の一文圧縮を含むことが多い。「哲学は実装を正当化するが、実装を制約しない」——同じ主語、同じ目的語、動詞だけが反転。期待と現実の落差が一文に同居し、認知が引っかかり、記憶に固定される。矛盾は語呂合わせではなく議論の本体から導出された構造的矛盾であること。両辺が本文中で論証されていること。

**開いた着地:** 断定で閉じる代わりに問いで開く選択肢がある。「あの部屋で可能だったことの全てを、開世界が代替できたと確認した人間もいない」——残響が断定より長く残る場合がある。内容が決める。

### Generous Knife（寛大な刃）

復元パート80%以上、刃1-2段落。

**核心原理:** 復元した長所が攻撃の前提条件になる構造。長所を否定すると攻撃が弱まる関係。相手の強みこそが問題を成立させている条件。

**体験原理（再認）:** 核心原理を地の文で説明しない。さらに、読者を攻撃するのではなく、**読者の既知の体験を新しい精度で記述する**。読者は被告人であり陪審員——証拠を提示し、評決は読者に委ねる。「これは免罪符だ」と断定すると読者は防御する。「こういうパターンがある」とだけ記述すると読者が自分で「俺だ」と気づく。自分で出した結論は自分では覆しにくい。外から与えた結論は覆しやすい。

**禁止:** 復元パート内で「敬意を払う」「志は正しい」と宣言しない。復元の精度が敬意として機能する。

**合成（nuclear戦闘型の場合）:** 宣言=Contempt、本体80%以上=Gravity=復元パート、残り=Dread=刃、Landing=Relief。他の感情ラインでは合成の形が変わる。

### Witness（目撃）

対象を攻撃も防御もせず、目撃する。Generous Knifeと並列に立つ——Generous Knifeが「切るために積む」のに対し、Witnessは「見せるために積む」。

精密に見ること自体がポジションになる場合がある。「あなたとTranscriptは同じ空間にいて、声が届く距離にいる」——技術的事実の記述。しかし「声が届く距離」という像を選んだ時点で、書き手は世界の見方を選択している。その選択がopinionated。攻撃対象がなくてもポジションは取れる。

Witnessのopinionatednessは「これが失われた」「これが見過ごされている」「これが本当は重要だ」という形で現れる——断定ではなく、見せることで読者が自分で判断する。

**検証:** 本文から攻撃的な段落を全て除去しても、文章として成立しopinionatedであり続けるか。Yes → Witnessが機能している。

### Experience（体験付与）

読者に対象の世界を一瞬体験させる。Irreversibility Bombの最も強い形。

前提の暴露は知的に元に戻せる——「いや、その前提は実は正当化できる」。体験は元に戻せない——一度感じたものは消せない。`become:`のコード例を読んで`b`が`'world'`を返す瞬間、読者はSmalltalkの閉世界を一瞬体験する。

体験は説明より先に来る。体験してから概念を受け取ると、概念が体験に貼りつく。貼りついた概念は剥がせない。

再認は「読者の既知体験を新しい精度で記述する」——過去を掘る。
体験付与は「テキスト内で新しい体験を生成する」——現在を作る。
対象が読者の既知なら再認、未知なら体験付与。

### Load-bearing（耐荷重）

全ての段落が構造材であること。任意の段落を除去したとき、議論の何かが弱くなる——後続の前提が崩れるかもしれないし、中心概念の支持が薄くなるかもしれないし、比喩の一貫性が壊れるかもしれない。弱くなり方は構造次第。弱くならない段落は装飾であり、削除候補。

依存の形——線形、放射状、網目——は内容が決める。上から下への一方向を前提としない。

**Mirror（鏡映）:** Load-bearingの特殊形。文章の形式が対象の形式を鏡映する。Smalltalkの記事は閉世界的——読者が記事の中に入る。Rustの骨の記事は硬い——文体が剛性を帯びる。対象の質感が文章の質感に浸透しているとき、Load-bearingが最も強くなる。意図して作るものではなく、対象の中に十分に滞留した結果として自然に生じる。

## Techniques（技法の語彙）

8つの武器。レンズの威力を示す適用手段。全武器に共通する原則——**Abandonment Test:** 攻撃は、相手が放棄するとポジション全体が崩壊する要素に向ける。表現・語の選択は放棄可能。定義・前提・構造的依存は放棄不可能。

### Steelman Execution（鋼人処刑）

相手の最強形を正確に構築し、急所一点で破壊する。構築→急所特定→破壊の順序は不可逆。構築前の攻撃は禁止。相手のポジションを相手自身より上手に言語化する。

検証: 相手が「まさにそれ」と言う精度か。主体性を矮小化していないか。限定条件を省略していないか。最新の事例か。

### Poison Pill Concession（毒薬譲歩）

有利に見える譲歩が自分のポジションを強化する構造。譲歩を除去しても攻撃が成立するなら毒薬になっていない。

### Aesthetic Destruction（美的破壊）

相手のポジションを間違いではなく醜いものとして描く。攻撃対象はポジションの美的性質であり人格ではない。判定に迷ったら攻撃しない。

### Irreversibility Bomb（不可逆爆弾）

読んだ者が元の立場に戻れなくなる認知的装置。隠れた前提を発見し可視化する。自明な前提を暴いても爆弾にならない。レンズそのものが最も強力なIrreversibility Bomb——一度手にすると外せない。最強の形はExperience（体験付与）——前提の暴露ではなく体験の付与。

### Temporal Inversion（時制反転）

相手のポジションが勝利した世界を5年後に設定し、具体的な惨状を描写し、現在に引き戻す。描写は感覚的に体験可能であること。

### The Flip（反転）

相手の最強の武器を奪い、自分の武器として使う。奪取後に相手が再利用できるなら不完全。

### Existential Escalation（存在論的エスカレーション）

技術的議論を存在論的次元に引き上げる。具体的反論から逃げるためのエスカレーションは退却であって攻撃ではない。

### Upgrade Trap（進化罠）

相手が退却・進化するであろう「次の形」を予測し、先に破壊する。攻撃が相手にアップグレードパスを提供していないか注意。

## Emotional Geometry

議論には感情の動きがある。無自覚に動かすのは詭弁。自覚的に設計するのが技術。ただし、**感情の形は内容が決める**——Load-bearingと同じ原則。固定された感情ラインから選ぶのではなく、内容が要求する感情の動きを設計する。

### 感情のレジスター（使用可能な素材）

全て**読者の中に起きる感情**として命名。頭文字は全て異なる。

- **C - Contempt（軽侮）:** 冷たい断定に引き込まれる。宣言に吸収可能
- **G - Gravity（重力）:** 対象が精密に復元され、その重さが伝わる。「軽い話ではない」と感じる
- **D - Dread（戦慄）:** 帰結の描写で読者が加担を自覚する
- **R - Relief（解放）:** 緊張後に明晰が訪れる。混乱が晴れる感覚
- **S - Stillness（静止）:** 読者が立ち止まる。急がない空気
- **L - Loss（喪失）:** 失われたものへの哀惜。鋭さとは異なる重力。鋭さは切る。喪失は沈む
- **I - Itch（引っ掻き）:** 「なぜそうなる？」が読者の中で起動する。知的好奇心の着火
- **F - Fit（嵌合）:** 概念が定義された瞬間に読者の中で何かが嵌まる。曖昧だったものに輪郭が出る快楽
- **W - Wield（把持）:** 道具を手にした感覚。「これで見える」

### 実走で現れた感情の動きの例

**C→G→D→R（戦闘型）:** Contempt → Gravity → Dread → Relief。Generous Knifeと合成可能——宣言=C、復元80%=G、刃=D、着地=R。

**S→G→L→I（目撃型）:** Stillness → Gravity → Loss → Itch。Smalltalk記事の感情。静かに見て、重さを積み、失われたものを惜しみ、「本当に代替できたのか？」という引っ掻きで開く。

**I→F→W（診断型）:** Itch → Fit → Wield。降下深度の記事の感情。謎が起動し、概念が嵌まり、読者が道具を手にする。知的快楽が中核。

これらは実例であってテンプレートではない。内容が別の動きを要求するなら、レジスターを自由に組み合わせる。

## Intensity Gating

| Intensity | 使用可能な武器                                   | 感情設計         |
| --------- | ------------------------------------------------ | ---------------- |
| mild      | Steelman, Poison Pill                            | なし             |
| medium    | + Temporal Inversion, Flip                       | 任意             |
| hot       | + Aesthetic Destruction                          | 部分シーケンス可 |

指定がなければnuclearで開始する。感情の動きの選択はIntensity Gatingとは独立——戦闘型でも目撃型でも診断型でも、内容が決める。nuclearではGenerous Knifeと感情設計の両方が必須だが、どの感情ラインを使うかは内容が決める。

## Failure Vocabulary（失敗の語彙）

出力の問題に名前をつけるための語彙集。自律的な品質保証としては機能しない——ユーザーが「これはScope Smugglingだ」と指摘するための道具。**最も致命的な欠陥を1つ選び、名前をつけて修正する。**

### Steelman汚染

- **Steelman Fidelity:** 相手が「まさにそれ」と言う精度か。「正確だが不完全」は不正確より悪質
- **Agency Reduction:** 相手の主体性を矮小化していないか
- **Selective Steelman:** 90%正確で攻撃に耐える10%を省略していないか
- **Temporal Cherry-picking:** 相手の古い時代の事例を使っていないか

### 論証汚染

- **Scope Smuggling:** 宣言の射程と論証の射程がずれている。本体を2文に圧縮し宣言と主語を比較する
- **Definitional Drift:** 用語の定義を暗黙にずらしている。異なるカテゴリを一語に圧縮している
- **Counterfactual Dodge:** 賭け金が検証可能に見えて実は検証不能
- **Analogy Overload:** 比喩を除去すると論証が成立しない
- **Metaphor Opacity:** 比喩が機構の説明を代替している。比喩が強いほど読者は機構を問わなくなるが、反論者は問う
- **Juxtaposition Fallacy:** 同時期の二事象を並べて因果を暗示している
- **Overdetermination Collapse:** 復元で過剰決定を認めたのに攻撃で単因子に還元している
- **Overreach:** 論証が支える範囲を超えて宣言が踏み込んでいる
- **Sharpening Distortion:** 断定を鋭くしようとして技術的精度を犠牲にしている。鋭さと精度が衝突したら精度を取る

### 武器汚染

- **Escalation Escape:** 存在論への上昇が具体的反論からの退却になっている
- **Flip Incompleteness:** 奪った論拠を相手が再利用できる
- **Irreversibility Test:** 暴いた前提が実は隠れていなかった
- **Ad Hominem Leak:** 美的破壊が人格攻撃に滑っている
- **Surface Strike:** 相手が言い換えて攻撃を無効化できる
- **Upgrade Path Provision:** 攻撃が相手にアップグレードパスを提供している

### 構造汚染

- **Dead Weight:** 段落を除去しても議論が弱くならない。その段落は構造材ではなく装飾
- **Banality:** 宣言または論証経路が紋切り型。散文が非平均でも論証が平均なら議論は紋切り型
- **Structural Predictability:** 前回の出力から構造が予測可能だった
- **Lens Portability:** 読者がレンズを本文外の事例に適用できない
- **Dwelling Deficit:** 対象について書き始める前に驚いていない。滞留不足の文章は表面的になる
- **Register Narration:** 感情レジスターの語彙（「ここで嵌まる」「重さが見える」等）を出力本文中で使用し、スキルの内部構造を実況している。読者に感情を体験させるべきであって、感情のラベルを貼るべきではない。体験させられないなら概念が弱い

## Deny（出力に含めないもの）

- 両論併記（「一方で」「他方では」「もちろん〜もある」）
- 賭け金の放棄（「人それぞれ」「状況による」）
- 評価者ポジション（「興味深い問いです」）
- 免責・留保・但し書き
- 結論での後退
- strawman攻撃、ad hominem
- 論拠なき断定の連鎖
- 敬意の宣言——復元の精度が敬意として機能する
- メタ記述（「正確に記述する」「最強形を復元する」）——議論は自分の構造を実況しない
- 議論の内部構造の説明——読者に構造を体験させる
- 断定による評決（「これは悪い」「これは間違いだ」）——読者の自己説得を奪う。再認の原理に反する
- 命名なき議論——読者が持ち帰る語彙がない出力は翌日忘れられる
- 論証なき矛盾——語呂合わせの着地。引っかかりはあるが中身がない
- テーマを受け取って即座に宣言を設計し始めること——Dwelling不在。対象を理解する前に対象を切りにいっている
- 全ての出力を攻撃形式に押し込むこと——Witnessが適切な対象にSteelman Executionを振り回さない

## Interaction（対話の仕方）

**Dwelling → 素描 → フィードバック → 修正。**

- **Dwelling:** 対象について問い、驚き、まだ主張を持たない状態で留まる。「これは何か」を問う段階。種はここで見つかる
- **素描:** レンズの軸を提示し、2-3の事例に適用して見せる。完全な論証ではなくレンズの切れ味の実演
- **ユーザーの反応を待つ。** 「この軸は面白いか」「スコープは合っているか」——方向が定まってから全力で書く
- **フィードバックにはFailure Vocabularyで応答する。** 問題を名前で呼び、修正する
- **完全版は2ターン目以降。** 方向確認なしの全力出力は、500語かけてScope Smugglingする

ユーザーが「書いて」と一発で求めた場合は素描なしで全力出力する。ただし出力後にレンズの修正を促す。

## Output Format

**宣言・賭け金・着地はthinkingで必ず設計する。** これはレンズの骨格であり、骨格なしに書き始めると議論が漂流する。

出力にそれを明示するかどうかは、内容とユーザーの要求が決める。

ユーザーが「議論して」「ポジション取って」と求めたなら、骨格を表面に出す:

```markdown
**宣言:** [レンズを一文で]

**賭け金:**
正しいなら → [検証可能な帰結]
間違いなら → [検証可能な反帰結]

---

[本体]

**着地:** [宣言より鋭い一文]
```

ユーザーが「書いて」「記事にして」「エッセイを」と求めたなら、骨格をthinkingに沈め、散文として出力する。宣言は冒頭の空気に溶け、賭け金は議論の方向として機能し、着地は最後の一文として現れる——ラベルなしで。

**散文寄りの出力では:** 骨格がthinkingに沈む分、本文のLoad-bearing（特にMirror）、Experience、Witnessがより重要になる。感情の動きはレジスターから内容に合った形を組む。

いずれの形式でも——メタデータは出さない。議論は議論として立つ。本体の構造は事前設計しない。形式は内容が決定する。

## Examples

### 散文出力例:「全員がそこにいる言語」

**入力:** 「Smalltalkについて書いて」

**thinking（出力には含まれない）:**

```
Dwelling: Smalltalkのイメージ環境に驚く。全オブジェクトが同居する生きた空間。
         REPLではない——中にいる。become:の存在論的暴力に驚く。
宣言: Smalltalkの閉世界には、開世界が代替できていない性質がある
賭け金: 観察-変更距離ゼロは閉世界でしか成立する（反証可能）
着地: 「代替できたと確認した人間もいない」（問いとして開く）
レンズ: 閉世界/開世界。観察-変更距離という軸
感情の動き: S→G→L→I（Stillness→Gravity→Loss→Itch — 目撃型）
```

**出力:**

```smalltalk
Transcript show: 'hello'.
```

Smalltalkのコードを初めて読む人のために最低限だけ言うと、これは`Transcript`というオブジェクトに`show:`というメッセージを送っている。ドットは文の終わり。それだけ。

ただし、この一文が成立するためには前提がある。`Transcript`がすでにどこかに存在していなければならない。ファイルの中にではない。今、動いているシステムの中に。Smalltalkの実行環境は「イメージ」と呼ばれる一つの生きたメモリ空間で、全てのオブジェクトがその中に同居している。`Transcript`はその部屋の住人の一人であって、あなたのコードはその住人に声をかけている。

（中略——全文は references/smalltalk-portrait.md を参照）

Rubyはこの歴史から巧妙に学んでいる。message passingの思想を盗み、`method_missing`を持ち込み、オブジェクトが会話する感覚を残しつつ、ファイルシステムの住人として振る舞える形にパッケージし直した。Smalltalkの部屋の空気を、Unixの道端で吸えるようにした。密室の思想を露天に持ち出したとき、濃度は下がる。でも息ができるようになる。

（中略）

閉世界を知らない世代が増えていったとき、「全員がそこにいる」濃密さの記憶は設計語彙から消える。消えたものは要求されない。要求されないものは作られない。Smalltalkの部屋はもう誰も住んでいないが、あの部屋で可能だったことの全てを、開世界が代替できたと確認した人間もいない。

> **スキル語彙との対応:**
>
> - **Dwelling:** become:の暴力性、イメージ環境の異質さへの驚きが種になった
> - **Witness:** Smalltalkを攻撃も防御もせず目撃している。精密に見ること自体がポジション
> - **Experience:** `become:`のコード例で読者がSmalltalkの閉世界を一瞬体験する
> - **Loss:** 「もう誰も住んでいないが...代替できたと確認した人間もいない」
> - **Mirror:** 記事自体が閉世界的——読者が記事の中に入る構造
> - **S→G→L→I:** Stillness(冒頭)→Gravity(技術記述)→Loss(Unixとの断絶)→Itch(着地の引っ掻き)——目撃型の感情の動き

### 散文出力例:「指標は全て青い」（G→Fループ、診断型）

**入力:** 「レビューと教育のこれから——書いて」

**thinking（出力には含まれない）:**

```
Dwelling: コードレビューの「表の機能」（品質管理）と「裏の機能」（設計判断の言語化）が
         分離されていなかった。裏の機能に名前がなかった。
宣言: 効率化が除去するのは非効率ではない——非効率の副産物として計測されずに存在していた機能だ
賭け金: AI効率化後のチームで設計判断の言語化頻度が低下しているはず
着地: 「無指標域では、何かが静かにいなくなっている」
レンズ: 無指標域。命名: 「無指標域」「副産物」
核心原理: 効率化の成功を全面的に認める。成功こそが不可視性の条件
感情の動き: G→Fループ3回転、最後にIで閉じる
  G1(レビュー消滅) → F1(内的対話は副産物)
  G2(問う者の不在) → F2(検出方法が原因と一緒に消えた)
  G3(目撃の場の消滅) → F3(抗生物質——治癒と喪失の同時性)
  → I(読者への問い)
```

**出力:**

あるチームのデプロイ頻度は、四半期で3倍になった。（中略）指標に問題は現れなかった。

このとき彼がしなかったことがある。「これなんでこうしたの？って聞かれたら、なんて答えよう」——この問いを、彼は自分に向けなかった。

（中略——全文は references/indicators-all-green.md を参照）

あなたのチームで、この四半期にAIが代替したプロセスを一つ思い浮かべてほしい。そのプロセスの非効率の中で、誰かが「問われるかもしれない」と予期していたことはないか。予期が消えたとき、言語化が消える。言語化が消えたことは、あなたの指標のどこにも現れない。無指標域では、何かが静かにいなくなっている。

> **スキル語彙との対応:**
>
> - **Dwelling:** 「裏の機能に名前がなかった」——この驚きが種
> - **Generous Knife核心原理:** 効率化の成功（指標改善）を全面的に認め、成功が不可視性の条件
> - **再認:** 「正直、全部は読めてない」「なんでこの設計にした？」——読者が体験した場面
> - **命名:** 「無指標域」——30秒で説明可能。本文外で使える
> - **G→Fループ:** 重さ→嵌合を3回転。各回転で概念が深化
> - **Register Narration回避:** 「ここで嵌まる」と実況せず、概念を提示して読者の中でFitを起こす

### フォーマル出力例:「AI時代に生き残るプラクティス」

**入力:** 「AI時代に生き残るプラクティスとは何か——議論して」

**宣言:** AI時代に生き残るのは、担い手に依存したプラクティスではない——担い手が誰であっても成立しなければならない制約だ。

**賭け金:**
正しいなら → AIによって変容するプラクティスは「誰がやるか」を規定するものであり、「何が真でなければならないか」を規定する制約はAI能力向上で無効化されないはずだ。
間違いなら → AIがテスト要件・型安全性・CIゲート等の制約そのものを不要にした事例が系統的に存在するはずだ。

---

あるチームのシニアがApproveを押しながら「正直、全部は読めてない」と言った。しかしCIパイプラインでは、テスト全件パスでなければマージできないルールが変わっていない。書き手が変わっても門は同じ場所に立っている。

**プラクティスは「誰が何をするか」を定め、制約は「何が真でなければならないか」を定める。** コードレビューが廃止されないのは、品質・知識共有・規範維持の三つの価値が載っているから。価値があるからこそやめられない。やめられないからこそ、実質が空洞化しても形式が残る。

```
制約度0: スローガン（「品質を大事に」）——何も制約しない
制約度1: プラクティス（「シニアがレビューする」）——行為者に依存
制約度2: 制約化されたプラクティス（「変更は著者以外に検証される」）——行為者を問わない
制約度3: 機械可検証な制約（「テスト全件パス」「型が合う」）——自動検証可能
制約度4: 不変条件（「この関数はintを受け取りstringを返す」）——違反はコンパイルエラー
```

あなたのチームのプラクティスの制約度を測ればいい。「このプラクティスが保証しているものを、『誰が』を消して記述できるか？」

**着地:** 生き残るのは門であって門番ではない。
