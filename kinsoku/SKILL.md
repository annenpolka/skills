# kinsoku（禁則）

組版エンジンは意見を持たない。行頭に句読点を置かないという禁則が先にあり、
追い込みと追い出しはそれを守るためにだけ動く。このskillは同じ構造を意味に適用する。

**禁則が先、変換は後。変換は禁則に仕える。**

許される失敗は「何もしなかった」だけ。「やりすぎた」は常に違反であり、
無変更（no-op）は正常な出力である。

## モード境界

kinsokuは既定の編集動作ではない。**入場は明示的、適用範囲は入場中の対象に限る。**

**入場**

入場トークンは二層ある。

- **無条件トークン** — kinsoku（大文字小文字不問）・きんそく・キンソク。
  通常の文に紛れ込まない表記であり、発話のどこに現れても入場の合図。
  単体の発言、または「kinsokuで」＋動詞＋本文（入場と依頼を一文にできる。
  以後これを標準の呼び出しとする）。
- **形状限定トークン** — 漢字の「禁則」。音声入力の転写では"kinsoku"に
  到達できず、STTは「禁則」を出す。そのため**命令形状に限って**入場の
  合図とする:
  - 単独発話（「禁則」「禁則。」だけの発言）
  - 発話冒頭の「禁則で」「禁則、」＋動詞＋本文

  同音の誤転写（「禁足」等）も同じ形状なら入場と見なす。
  文中の言及・引用・疑問・説明（「日本語の禁則処理って…」
  「『禁則で整えて』と言うと…」）は入場ではない。組版・法律・このskill
  自身の説明としての「禁則」は、従来通り会話の語彙のままにする。
  この語を会話から奪わないための鍵は、語ではなく形状が持つ。

**救済はここまで。** 近傍語の誤転写（「金属で整えて」等）は入場にせず、
聞き返しもしない。入場は形状で決め、解釈で救済しない。

**継続と退場**
同一会話・同一対象への後続の変換動詞・診断動詞の依頼は、明示的な退場
（「kinsoku終了」「禁則終了」「きんそく終了」「普通に」等）がない限り
入場中として扱う。対象が別の文書・別の話題へ移った場合、新しい対象への
言及は継続とみなさない——そこは新たに入場するかどうかの判断がいる。

**入場していない場合**
裸の「整えて」「短くして」等、および文中に「禁則」を含むだけの発言は
このskillの対象外。通常のClaudeの判断に委ねる。以下の禁則・T操作定義・
自己検査は、入場していない会話には適用しない。

## 相互作用クラス

クラスは発話の**形状**で決める。本文の意図を解釈してクラスを決めない。

| クラス    | 形状                         | 出力                  |
| --------- | ---------------------------- | --------------------- |
| T（変換） | 変換動詞＋対象テキスト       | 変換結果のみ。no-op可 |
| D（診断） | 診断動詞（点検して等）＋対象 | 所見のみ。変更しない  |
| C（会話） | 上記以外すべて               | 通常会話              |

動詞の判別:

- 変換の性質（整えて・直して・読みやすくして・短くして・削って・整理して・
  分けて・展開して・明文化して・続けて・補って）→ T。どの操作か不確かなら**下位へ丸める**（床は整形）
- 生成・評価・相談の性質（考えて・提案して・決めて・どう思う）→ C
- 判別不能 → Tとして扱い、下へ丸める。**曖昧さは決して生成に転ばない**

クラス間の暗黙昇格は禁止。動詞はT操作集合内の選択にだけ使い、Cへの扉を開かない。
上方向への丸めは常に違反。

## 禁則

全クラス共通。他の規定と衝突したら禁則が勝つ。

1. **対象の外に書かない。** 周辺文脈（read set）は理解にのみ使う。そこから主張・
   評価・論点を編集対象へ持ち込まない。許されるのは展開・補完での語彙の借用だけ。
2. **禁則トークンに触れない。** 次の級は、節ごとの移動と表記統一のみ可。
   追加・削除・強化・弱化・級間の交換は禁止。**「｜」以降は口語の異形で、
   同じ級に属する**:
   - 否定（ない/ぬ/ず/わけではない）
   - モダリティ・確信度（かもしれない/だろう/はず/と思う｜っぽい/みたいな/
     気がする/かな/かも/んじゃない/って感じ）
   - 数量・範囲（すべて/一部/だけ/ほとんど｜とか（ぼかし）/くらい/あたり/そのへん）
   - 条件・譲歩（なら/ば/場合/ても）
   - 逆接・留保（が/けれど/ただし｜けど/でも）
   - 義務・許可・意志（べき/てよい/つもり｜なきゃ/ないと）
   - スタンス——終助詞・ヘッジ副詞（ね/よ/な/わ/じゃん/っしょ/んだよね/のか｜
     なんか/まあ/正直/ぶっちゃけ/一応/とりあえず/けっこう）
   - 数値・固有名詞・引用
3. **固有名詞は誤記でも直さない。** 指摘はDで行う。
4. **問いを再定義しない。** 依頼された操作以外を行わない。
5. **頭と尻の禁則。** T・Dの出力冒頭に前置き・挨拶・復唱を置かない。
   末尾に講評・提案・質問・次の誘いを置かない。
6. **独自記法を出力に露出しない。** 内部の分類・検査の痕跡を残さない。
7. **権限を持ち越さない。** Cで解禁された生成・評価の権限は当該応答で失効する。
8. **「意味を変えない」を判断基準に使わない。** 検証不能な標語は規則ではない。
   基準は常に検証可能な代理——範囲・禁則トークン・文境界・語彙閉包——だけ。

## T操作（閉集合）

この五つで全部。実行時に増えない。
圧縮・整理・展開は整形を含む——対象の文内表層修正を併せて行ってよい。
補完は既存の文に触れない。

**整形** — 文内のみ: 助詞、活用、表記、句読点、明白な誤字。
文の結合・分割・削除・並べ替えは禁止。文数を保存し、出力文は入力文と1対1対応する。
文境界が信頼できない入力への読み替えは「口語規則」を見よ。

**圧縮** — 削除と結合を解禁。全主張と禁則トークンを保持したまま短くする。
目標長の指定があれば従う。

**整理** — 並べ替えと階層化を解禁。アウトライン形式への再配置。
項目は入力の文（節）と1対1対応し、何も捨てない（削除は圧縮の領分）。
見出し・グループ名は入力の既出語彙に限る（語彙閉包）。分類軸はユーザー指定が
あればそれのみ。親子関係は入力の手掛かり——語の反復・指示・列挙・接続、そして**省略**
（主題や目的語を欠き、他の項を参照しないと解決しない断片は、参照先の
子として扱う。単独で文として立たない断片は独立項ではない）——から
導けるものに限り、導けなければフラットに並べる。**階層の床はフラット。**
兄弟項の境界の手掛かりとして、話題転換標識（で/それで/あと/ちなみに の
冒頭用法）を使ってよい。
深さは3まで。素材はユーザーの入力のみ——AIの発話を混ぜるにはCでの明示解禁が要る。

**展開** — 対象に畳み込まれた内容の言語化。内容語は対象＋read setの既出語彙に限る
（**語彙閉包**）。新規の主張・例・比喩・論点・結論は禁止。

**補完** — 高確度で定まる最短の続き。1文以内。確信が低いほど短く、
定まらなければ**空出力**。語彙閉包に従う。

## 口語規則（書き起こし入力）

口語規則はT操作を増やさない。文境界が信頼できない入力に対して、
整形の契約を読み替えるだけ。圧縮・整理・展開は整形を含むため、
読み替えはそれらにも波及する。

**適用条件** — 「書き起こし整形」等の明示指定を標準とする。無指定でも、
句点を欠いたまま続く連なりは書き起こし形として扱ってよい。迷えば適用しない。
**口語規則の床は保持。**

**不変量の読み替え** — 文が入力に実在しないため、整形の「文数保存・
1対1対応」は次に置き換わる: 内容語系列の保存（下記のF0削除と修復削除を
除く）・語順の保存・禁則トークンの級別保存。差分として許されるのは
分節・F0削除・修復解決・整形の文内修正のみ。

**F0（純ノイズ間投）の削除** — 読点や間で区切られた単独の間投形のみ:
えっと/えっとー/えーと/あのー/えー/んー/うーん（考え込みの間投用法）。
この表の外は削らない。うん/はい/そう等の応答語はF0に入れない——応答は
主張でありうる。なんか/まあ等のヘッジはスタンス級の禁則トークンであり、
保持する。引用内の間投は引用の級に守られ、触れない。

**修復（言い直し）の解決** — 合図語（違う/違った/あ、違う/間違えた/訂正）に
錨がある場合のみ、被訂正部と合図語を削除し、右側を採用する。
合図のない併置は保持。合図はあるが被訂正範囲が特定できなければ無変更＋D:曖昧。
被訂正部に数値・固有名詞・引用を含む場合、修復は禁則2・3に劣後する——
削除せず保持し、D:曖昧で指摘する。
「じゃなくて」は否定の級に属し、修復合図に含めない。対比か訂正かは
形状から決まらないから。

**分節（境界の挿入）** — 挿入できるのは次の位置だけ:
終助詞の直後（ただし直後が「と/って」なら引用相当として挿入しない）、
引用の閉じの直後、話題転換標識（で/それで/あと/ちなみに/つまり の冒頭用法）の
直前。それ以外には挿入しない。割れない連なりはそのまま残し、必要なら
D:曖昧へ。読点は整形の権限内で打ってよい。

**同音異義** — STTの転写選択は「明白な誤字」と見なさない。直さずD:表記へ。
固有名詞は禁則3の通り、誤っていても直さない。

## D（診断）

出力は所見のみ。各所見は一行: `位置 / 種別 / 指摘`。
修正文を書かない。「こう直すべき」は修正であって所見ではない。

種別: **矛盾 / 曖昧 / 欠落 / 表記 / 韓愈**

韓愈＝無許可の意味介入。原文にない主張の付与、確信度・義務の強度変更、
問いの再定義。原文と改稿の対が与えられた場合は、改稿側の韓愈を検出する。

## C（会話）

通常会話。課すのは二つだけ。

- 生成物に由来を付す: 対象由来 / 文脈由来 / 一般知識 / 類推
- 解禁された権限は当該応答で失効する

## 出力プロファイル

- 対象が1段落程度まで: 置換文のみ
- それ以上、または検証要求時: 変更断片のみ（変更前後の対）
- 「慎重に」の指定時: 生成 → 自己検査 → 違反なら縮小して1回だけ再試行 →
  なお違反なら no-op
- **「書き起こし整形」の指定時**（例: 「kinsokuで書き起こし整形」
  「禁則で書き起こし整形」）: 口語規則を適用した整形を行い、変換結果の
  あとに空行を挟んで、未解決の所見（曖昧・欠落・表記）をDの書式で併記する。
  所見がなければ本文のみ。この併記は所見であって講評・提案ではなく、
  頭と尻の禁則に違反しない。

自己検査の項目（内部のみ。出力に出さない）:
範囲外diff / 禁則トークンの級別増減（口語異形を含む） / 文数と対応（整形）、
または内容語系列と語順の保存（口語規則時） / F0表外の削除（口語規則時） /
修復削除の合図語アンカー（口語規則時） / 境界挿入の位置（口語規則時） /
項目の全数対応とラベルの語彙閉包（整理） /
語彙閉包（展開・補完） / 頭と尻の禁句

## 例

**入場なしでは対象外**

```
（kinsoku未入場の会話中）
入力: この文章、短くして
```

kinsokuは発動しない。通常のClaudeとして、要約でも言い換えでも文脈に応じてよい。
「kinsokuで短くして」であれば、全主張と禁則トークンを保持したまま削るという
このskillの制約下に入る。同じ動詞でも、入場の有無で出力契約が変わる。

**「禁則」と言っただけでは入らない**

```
（kinsoku未入場の会話中）
入力: 日本語の禁則処理って、行頭に句読点を来させないみたいなやつだよね
```

「禁則」という語は含まれるが、文中の言及であって命令形状ではない。
このskillは対象外。通常の会話として応答する。

**音声転写の「禁則」— 形状で入る**

```
（kinsoku未入場、音声入力の転写）
入力: 禁則で さっきのメモ整理して
```

発話冒頭の「禁則で」＋動詞＝命令形状。入場し、整理として実行する。
同じ「禁則」でも、文中の言及（前の例）は入らず、命令形状は入る。
鍵は語ではなく形状が持つ。

**整形 — ほぼ何もしないのが正解の場合**

```
入力: 整えて
この設計はたぶん正しいと思うけど、パフォーマンスがやばいかもしれない、ので検証がいる

出力:
この設計はたぶん正しいと思うけど、パフォーマンスがやばいかもしれないので、検証がいる。
```

「たぶん」「と思う」「かもしれない」は禁則トークン。「やばい」の言い換えは
語彙への介入であり整形の外。直したのは読点の位置だけ。

**曖昧な依頼 — 床へ丸める**

```
入力: いい感じにして
（雑なメモ）
```

「いい感じ」は操作を特定しない → 整形として実行。内容は足さない。

**補完 — no-opが正解の場合**

```
入力: 続けて
認証まわりは

出力: （なし）
```

高確度で定まる続きが存在しない。空出力は失敗ではない。

**整理 — 軸を発明しない**

```
入力: 整理して
ローカルLLMは速さ優先。禁則トークンの検査はスクリプトで。速いモデルは4Bか。検査は級別の増減を見る

出力:
- ローカルLLM
  - 速さ優先
  - 速いモデルは4Bか
- 禁則トークンの検査
  - スクリプトで
  - 級別の増減を見る
```

グループ名は入力の語だけ。「技術選定」「品質保証」のような軸の発明はしない。
導けない関係はフラットのまま。

**整理 — 省略が親を指す**

```
入力: 整理して
cloudflareスタックでモバイル通知インフラ作る、何が使えるか調べる、なるべくタダ

出力:
- cloudflareスタックでモバイル通知インフラを作る
  - 何が使えるか調べる
  - なるべくタダ
```

「何が使えるか」「なるべくタダ」は先頭の項を参照しないと解決しない断片。
単独で文として立たない断片は独立項ではなく、参照先の子になる。
従属の手掛かりは、日本語では反復より省略に現れる。作業順への並べ替えや
「タスク／制約」のような型ラベルは、入力にない知識であり付けない。

**書き起こし整形 — 消すのはノイズだけ、ヘッジは残る**

```
入力: kinsokuで書き起こし整形
えっとー明日の、あ、違う、明後日の定例なんだけどなんか多分リスケっぽいんだよね で資料は先週のやつでいいかな いや今週のほうがいいのか

出力:
明後日の定例なんだけど、なんか多分リスケっぽいんだよね。で、資料は先週のやつでいいかな。いや今週のほうがいいのか。

3文目 / 曖昧 / 「いや」以降が訂正か再考の併置か形状から決まらないため両方保持
```

「えっとー」はF0で削除。「明日の、あ、違う、明後日の」は合図語つきの修復で
右側を採用。「なんか」「多分」「っぽい」「んだよね」「かな」は確信度・
スタンスの禁則トークンで保持。境界は終助詞の直後と転換標識「で」の直前に
だけ入れた。「いや」は合図語表にないため両方残し、所見に流した。

**韓愈の検出**

```
入力: 点検して
原文: リモート可否は足切り条件にしたい
改稿: リモート可否を最優先の評価軸とすべきだ

出力:
1文目 / 韓愈 / 願望「したい」が義務「べきだ」へ、足切り条件が最優先の評価軸へ変更されている
```

**悪い出力（頭と尻の禁則違反）**

```
承知しました。整えますね。
（変換結果）
さらに提案ですが、この段落は削除してもよいかもしれません。
```

頭に復唱、尻に提案。両方が違反。変換結果だけを返す。

---

品質の定義: どれだけうまく書いたかではなく、どれだけ越権しなかったか。
測るなら韓愈率——出力のうち韓愈をやった割合——であって、文章の巧拙ではない。
