# ACP Maintenance Contract

This file is for maintaining `scripts/grok-delegate.mjs`, not for ordinary delegation.

## Process boundary

The client uses UTF-8 newline-delimited JSON-RPC over stdio. Root options precede the agent command:

```text
grok --no-auto-update --cwd <transaction-workspace>
  --permission-mode default --disable-web-search
  --deny MCPTool --deny WebFetch --deny WebSearch
  --deny <dangerous Bash classes> --no-subagents
  [--sandbox PROFILE] [--model MODEL] [--reasoning-effort LEVEL]
  agent --no-leader stdio
```

Never add always-approve, bypass permission mode, trust, reauthentication, plugin directories, a shared leader, or a fallback that drops the requested sandbox. Flags are defense in depth; reverse permission handling, content-sensitive Git collection, and the selected execution profile are the enforcement boundary. Transactional isolation alone is not an OS security boundary against same-UID code. Hardened mode is supported only when its macOS verifier profile passes the complete affirmative pre-spawn probe; other systems fail closed.

The Grok child receives a minimal allowlisted environment plus explicitly frozen inherited names. In both profiles the wrapper owns `HOME`, `GROK_HOME`, `GROK_AUTH_PATH`, the XDG homes, and all compatibility controls; task `inheritEnv` cannot override them. Loader/runtime/shell/Git/proxy/TLS control variables and all Grok or provider-routing prefixes are rejected, with `XAI_API_KEY` the sole XAI exception. The transaction manifest stores one private aggregate hash over each inherited name's presence and value, never the raw values; a changed value or presence on `continue` fails nonrecoverably before Grok starts. Effective `PATH` must consist only of nonempty absolute entries. Before the first Git operation, `start` binds that exact `PATH` plus realpath, regular-executable metadata, and content fingerprints for Git and Grok; it also binds every verifier and delegated-shell `argv[0]`. `continue` rechecks all of them before reset or Grok, and `apply` rechecks `PATH` and Git before touching the source. Only aggregate hashes persist. It creates transaction-private runtime and Grok homes, writes a minimal configuration with `permission_mode = "ask"`, `default_selected_permission = "allow_once"`, and `remember_tool_approvals = false`, and forces Claude/Cursor/Codex skills, rules, agents, MCPs, hooks, and sessions to the documented literal `false`. Explicit Ask rules cover Edit, Write, and Bash; deny rules cover MCP, web, secret-path reads, dangerous Git commands, removal, and common network commands. These controls do not prove that repository-native `.grok` or `.agents`/`AGENTS` files, or system/MDM layers, are absent. Regardless of Grok-side configuration, a mutation without the wrapper's matching reverse `allow_once` grant fails the audit.

Hardened mode requires the inherited `XAI_API_KEY` route and never copies host auth into the transaction. Hardened verifiers use a private default-deny `sandbox-exec` profile with global reads, denied network/link operations, and writes allowlisted only to the candidate worktree, verifier home, and verifier temp; source, source Git metadata, and candidate `.git` are explicitly denied. The complete allowed/denied probe runs before any Grok spawn. An unavailable, unsupported, or rejected profile is `verifier_sandbox`, never an unsandboxed retry.

Trusted-local mode may instead use `cached_token`. The wrapper resolves the operator-controlled cached-auth location before replacing the child environment, requires the basename `auth.json`, then requires its real path to be disjoint from the source worktree, Git/common-Git directories, and state root. The auth source must be a non-symlink regular file owned by the current UID, mode `0600`, link count one, bounded valid JSON with no duplicate object keys, and stable across an `O_NOFOLLOW` read. Its content is never copied to the transaction and its path, content, and hash are not written to the manifest or public output. Every sufficiently long JSON string scalar is held only in memory as an exact-value redaction target for streamed messages and the structured report. This does not cover encoded or transformed values. The private policy also denies Read/Grep access to `auth.json`, and Bash carrier screening rejects `auth.json`; these are defense in depth, not a same-UID confidentiality boundary. The child receives only the validated path through wrapper-owned `GROK_AUTH_PATH`; the wrapper fingerprints the source before and after every round and makes any detected change nonrecoverable. Every normalized stream event for a cached-auth round is held in memory until that post-round fingerprint succeeds; an auth mismatch or any round error drops the entire queue. If post-round auth cannot be parsed and therefore cannot extend the redactor, dynamic permission decisions/paths/argv, provenance, report, candidate, and events are suppressed; only fixed audit codes and numeric counts persist. That check is after-the-fact: auth refresh or a same-UID mutation may already have changed the host file, and the wrapper neither prevents nor rolls it back. Trusted-local provides no hostile same-UID isolation.

## ACP lifecycle

1. Send `initialize` for protocol version 1 with filesystem read/write and terminal capabilities disabled.
2. Authenticate with `xai.api_key` when present. Only trusted-local mode may fall back to `cached_token`.
3. Send `session/new`, or `session/load` using only the session ID bound to the same transaction manifest. The CLI accepts no caller-supplied session ID and rejects a cross-transaction binding. This is not a cryptographic seal against same-UID state-and-code tampering.
4. Suppress load replay from public output, but still audit any tool execution update received during load as execution outside the current prompt. Enable current-turn collection before sending the prompt request.
5. Send exactly one `session/prompt` for the round. Only its matching JSON-RPC response completes the round.
6. After the matching prompt response, keep stdin open through a bounded activity-reset inbound-quiescence barrier. Every inbound line advances a generation and restarts a short quiet window; a reverse-response flush also restarts it so follow-up requests get an event-loop poll opportunity. The round timeout/cancellation remains the outer bound. Await and answer every in-flight reverse request, including JSON-RPC error responses, and keep each response in-flight until the child-stdin write callback confirms its bytes were flushed. Only after a stable quiet generation and empty reverse set may the client flush/end stdin, finalize the permission audit, and drain/reap the child.

The session metadata fixes `yoloMode`, `autoMode`, and `askUserQuestion` to false and `mcpServers` to an empty list. A timeout or SIGINT sends the `session/cancel` notification, waits the frozen grace period, then uses TERM/KILL if needed. Exit codes are 124 for timeout, 130 for SIGINT, 2 for usage, and 1 for other failures.

## Reverse permission requests

Handle reverse requests concurrently with pending client requests. Capture is enabled before sending the current `session/prompt`. Consume each valid JSON-RPC reverse-request ID globally before method dispatch, so an unknown method cannot release its ID for a later permission request. A duplicate permission request is recorded as a rejected audit decision without entering its asynchronous path/argv handler; an unknown method returns `-32601`, while a duplicate ID returns `-32600`. A permission request is eligible only during the active prompt, only when `params.sessionId` equals the active session, and only with a valid previously unused request ID plus a nonempty, previously unused `toolCallId`. Every present tool-call ID alias in the request or update must be the same exact value. A present permission-envelope status is merged into that ID before deciding: only pending/queued is nonexecution, while running/completed/failed and the other execution statuses prohibit a grant. Because path resolution is asynchronous, the wrapper rechecks the ID's revision, identity, lifecycle, path, argv, and invalidation state immediately before returning `allow_once`; a concurrent fragment revokes the grant.

Tool identity is exact. Strong `kind`/name fields must equal an allowlisted identity; unrelated words such as `Credit`, `Rewrite`, and `Shellfish` stay unknown. Composite identities such as `WebEdit` and `MCPWrite` are ambiguous and rejected, never reduced to an edit/write substring. When current x.ai tool identity metadata is present, it must agree with the parsed tool kind. Only a server-provided `allow_once` option may be selected. Persistent or session grants are never selected.

- Edit/Write: discover every path without echoing raw input. Resolve existing components and reject symlinks. Every path must stay below the transaction workspace, match frozen write scope, and stay outside protected paths. A later execution update must canonicalize to exactly the same path set; equivalent relative and `file:` URI representations may agree, but a missing, added, changed, or outside source/destination path is a violation.
- Bash: accept a direct argv array or conservatively tokenize a simple `command` or `cmd`. Multiple argv/command representations must parse to exactly the same token array; conflicting representations are ambiguous and rejected. Reject control operators, metacharacters, redirects, substitutions, newlines, unsafe escapes, shell wrappers, `env`, `xargs`, `sudo`, network commands, MCP/secret access, package installation, commit, push, reset, stash, checkout, worktree, and removal operations in both string and direct-argv carriers before exact/prefix matching. Then require an exact or prefix match against a frozen shell permission. A later execution update must parse to the same argv that received permission.
- MCP, web, network, secrets, unknown tools, or unparsable requests: choose `reject_once` when supplied, otherwise cancel.
- Unknown reverse methods: return JSON-RPC `-32601`.

Treat ACP v1 `tool_call_update` as a delta, not a complete replacement. A `tool_call` establishes a new `toolCallId`; later updates may omit status, identity, path, argv, locations, content, or raw input, and omitted fields inherit only from that same ID. No update, including a statusless enrichment, may establish an unknown ID. An update cannot create a terminal-only ID, reuse an ID after a terminal status, or replace any present security projection. Statusless enrichment after the establishing call and before permission is descriptive and is not execution evidence.

When exact `_meta["x.ai/tool"]` metadata is present, it is the native policy identity. The envelope must use the known version and an exact allowlisted namespace/`kind`/`name` tuple, a boolean `read_only` consistent with that identity, a string display label, only known envelope keys, and an object `input` when present. The supported observed tuples are namespace `opencode` with `write/write`, `edit/edit`, or `execute/bash`; namespaces `grok_build` and `grok_build_concise` use `read/read_file`, `edit/search_replace`, or `execute/bash`. They map respectively to read, write, edit, or bash policy classes. The label and outer title never authorize. ACP's outer schema-lowercase display `kind` is a separate compatibility axis: native read requires exact `read`, write/edit require exact `edit`, and bash requires exact `execute`. Unknown values, case/substring near-matches, incompatible native/display pairs, or a same-ID change to the exact native identity fail closed. After a native identity is established, an x.ai-omitted delta may omit identity completely or carry only an exact compatible outer display kind; `name`/`toolName`, legacy native-looking `kind` values such as `write` or `bash`, and case variants are contradictions, not legacy fallback. Title alone remains descriptive. Legacy exact strong kinds are a compatibility path only before any x.ai identity exists for that ID.

Every path or argv carrier present in each fragment is canonicalized and compared with the already-observed state and, after permission, with the exact permission snapshot. The generic carrier visitors inspect the entire `_meta["x.ai/tool"].input` object as well as raw input, locations, and diff paths: path, URI, source/destination, old/new, and argv/cmd/command representations must all agree, while suspicious unknown carrier keys fail closed. Equivalent relative and `file:` representations may agree; an added, missing-from-a-present-projection, changed, ambiguous, malformed, or outside carrier fails closed. Write and Edit share mutation-policy handling, while their exact native identity and canonical path set remain distinct state.

Track observable tool-call, reverse-request, and permission IDs internally, preserving the exact native identity, compatible display kind, canonical paths, tokenized argv, and lifecycle status for each ID. Permission selection alone is not execution evidence. Only a same-ID terminal status after the matching `allow_once` grant can confirm execution, using the path/argv already matched at permission time. `running`, `in_progress`, `completed`, `succeeded`, or `failed` before a grant is an unapproved attempt; a permissionless mutation terminal is also rejected. The sole non-execution terminal exception is `failed`/`cancelled` after the wrapper explicitly rejected that same permission request. After a grant, `failed` still represents a potentially partial execution attempt. A grant without a terminal status, changed identity/path/argv, duplicate request ID, pre-grant execution, unknown or terminal-only ID, terminal reuse, mismatched session, execution during load/outside capture, unknown status, or unknown/unapproved executed tool is a policy violation even though it occurred only in the clone. A round with a forbidden or malformed permission audit is not recoverable.

## Normalization and privacy

Never print raw ACP, initialize/auth metadata, thoughts, raw tool input/output, MCP configuration/extensions, child stderr, secrets, session IDs, or full verifier logs. In particular suppress `_x.ai/mcp/servers_updated` and all unknown extensions. Build a memory-only exact-value redactor from every nonempty explicitly inherited environment value of meaningful length, cached-auth JSON string scalar, private path, and known ACP session ID. A new session ID is added before prompting; a continued session is present from round start. Apply exact redaction before control-character sanitation and truncation for every public field. Buffer raw `agent_message_chunk` text within the 64 KiB/artifact cap, join the whole turn, then redact and emit at most one message event after successful prompt completion and inbound quiescence. If the cap is exceeded, publish none of that turn text or report, so a kept prefix cannot expose part of a secret whose suffix overflowed. Timeout and other round errors do not flush buffered messages. The full round redactor is passed through failure handling only in memory and removed before persistence. A partial candidate is not written as a patch or manifest candidate unless post-round auth inspection completed and the redactor leaves the entire prospective patch unchanged; this prevents secret-bearing failure paths or content from entering either public changed paths or private partial artifacts. This does not prevent deliberately transformed or encoded exfiltration and must not be described as doing so.

Public intermediate events are limited to one turn-complete assistant message, sanitized tool kind/status/repository-relative paths, sanitized plan entries, and numeric usage. Exact inherited values are also removed from every public dynamic candidate, permission, and agent-report path. Raw carrier values and the accumulated executed-path ledger remain transaction-private; neither its field name nor its hash is part of normalized output. Default mode prints exactly one result line. Stream mode adds a strictly increasing `seq` and prints exactly one final result as its last line. Cached-auth stream events of every type are released only after the unchanged-auth check succeeds.

## Structured agent report

The canonical prompt contains the frozen task except that the real source path is replaced by `.` as a transaction-workspace marker. It includes scope, allowed tokenized commands, anti-cheat rules, prohibitions on network/install/commit/push/stash/reset/branch/worktree, and the wrapper's prior verifier evidence for continuations. It asks for:

```json
{
  "schemaVersion": 1,
  "summary": "bounded summary",
  "changes": [{"path": "repo/relative", "description": "what changed"}],
  "verificationNotes": ["non-authoritative observation"],
  "risks": ["known risk"],
  "residue": [{"id": "human-item", "status": "pending_human_review", "note": "why"}]
}
```

Only these normalized fields may be surfaced, always under `agentReport.authoritative: false`.
