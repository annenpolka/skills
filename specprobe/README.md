# specprobe

仕様の曖昧さ・空白・矛盾を、**未決定の事項と、それが問題になる具体的なケース**として取り出すAgent Skill。

通常は原文の読解、決定事項の整理、質問のスクリーニングで進める。判断を絞り込める箇所だけ、Jevによる意味照合や小さな形式モデルの反例探索を使う。すべての仕様を形式化するためのフレームワークではない。

## 使う

Agent Skills対応ホストへ、この`specprobe/`ディレクトリを配置する。入口は[SKILL.md](SKILL.md)。名前・descriptionと、必要なときだけ読む参照ファイルを持つ構成。

呼び出し例:

```text
この認証仕様をspecprobeでレビューして。
曖昧さと未規定事項を、挙動が分かれる具体例付きで出して。
原文は変更せず、必要な部分だけ小さなモデルで確かめて。
```

```text
このPRDとAPI契約の矛盾・例外・境界条件を調べて。
既存コードは現状の証拠として扱い、仕様の正本とは混ぜないで。
実装自由度まで仕様抜け扱いしないこと。
```

Claude Codeの個人Skillディレクトリへコピーする例。ZIPを展開した親ディレクトリで実行する。既存の同名ディレクトリがある場合は上書きせず停止する。

```bash
mkdir -p "$HOME/.claude/skills"
test ! -e "$HOME/.claude/skills/specprobe" && \
  cp -R specprobe "$HOME/.claude/skills/specprobe"
```

`annenpolka/skills`に取り込む場合は、他のSkillと並ぶルート直下の`specprobe/`として配置できる。リポジトリやREADMEの実変更、インストール、commit/pushはこの配布物の作成では行っていない。

## 処理の流れ

```text
仕様原文と正本の範囲を確認
  → 決定事項・仮定・未決定事項を分離
  → 必要なケースから質問を作る
  → 質問自体をスクリーニング
  → 原文・必要に応じJevで照合
  → 必要な箇所だけ反例／差分挙動を探索
  → 根拠と選択肢を添えた判断用の報告
```

初回は高影響の候補12件程度、形式モデルは最小の1スライスを目安にする。これは作業予算であって、完全性の保証ではない。

## 既存Skillとの役割分担

| 要素 | 役割 |
|---|---|
| specprobe | 何が決まっていないか、どのケースで困るかを発見する |
| qlintの検査原則 | 質問・資料・用途の契約を確認する。CLI依存にはしない |
| jev-crosscheck | 小さな意味関係と具体的な資料充足性を既存helperで照合する |
| 形式手法／有限探索 | 定義したモデルの反例や候補間の差を探索する |
| spec-interview | 対話が求められたとき、残った重要な判断を解決する |

`jev-crosscheck`と`spec-interview`は同梱・複製していない。インストールされている場合に、その時点の指示を読んで使う。外部送信は既存の許可範囲とinspect/sendを守る。Jevが利用できなくても、原文を根拠としたレビューは継続する。

## 内容

- `SKILL.md` — 起動条件、調査手順、停止条件、出力契約。
- `references/` — 質問検査、gap分類、Jev連携、形式手法、報告テンプレート、一次資料。
- `examples/` — ログイン失敗カウントの未決定例と、比較用の二つの有限モデル。
- `scripts/compare_fsm.py` — 小さな全域的・決定的有限モデル同士の差分探索。Python 3.10以上、標準ライブラリのみ。
- `tests/` — 補助スクリプトの単体テストと、Skillを評価するための16ケース。
- `validation/` — 実際に実行した検証の結果。

## 補助スクリプトを試す

`specprobe/`内で:

```bash
python3 scripts/compare_fsm.py \
  examples/reset-on-success.json \
  examples/preserve-on-success.json

python3 -m unittest discover -s tests -p 'test_*.py' -v
```

比較スクリプトは、同じ入力列で二つのモデルを進め、指定した観測が分かれる最短の入力列を探索する。入力JSON内のコードや式は実行しない。遷移が欠けている場合も勝手に補完しない。

終了コードは`0`が探索結果（差分発見も含む）、`2`が入力・I/Oエラー、`3`が資源上限で判定不能。二つの候補のどちらを採用するかや、どちらが自然言語仕様に準拠するかは判定しない。

## 検証状況

作成日: 2026-09-18。v0.1.0。

実施した検証:

- 補助スクリプトの単体テスト30件。
- 同梱ログイン例の実行。観測を`locked`としたとき、4イベントで差が出る最短の例を得た。
- Skillのfrontmatter、相対リンク、JSON、Python構文などの構成検査。

実施していない検証:

- 実際のホストでのSkill読み込み・エージェントによるレビュー評価。
- Jev実API呼び出し、意味判断の精度・校正の測定。
- Quint/TLA+/Alloy/Z3による外部モデル検査。この配布物には利用手順を収録している。

単体テスト30件はSkillの検出精度を測るものではない。`tests/behavioral-cases.md`の16ケースも、実行済み結果ではなく評価仕様。仕様の網羅的完全性、実装全体の正しさ、採用すべきポリシーは保証しない。

## 設計上の要点

**情報不足はfalseではない。候補モデルの挙動差は、原文の曖昧さの証明とは別である。**

原文に明示された事項、導出、仮定、意図的な自由度を混ぜない。モデルを動かすために仮定を追加した場合は、その仮定に依存する結論だけを返す。反例がないときも、探索した領域と未検査の範囲を併記する。

外部仕様と既存Skillの参照記録は[references/sources.md](references/sources.md)にある。
