# Scene Walker

## このスキルは何をするか

AIに「認証機能を実装して」と投げると、標準的な実装が出てくる。
テストが通る。動く。

でもAIはもっと知っている。セッション固定攻撃。未成年の保護者同意。
App Storeの審査リジェクト基準。退会ユーザーの外部キー処理。
知っているが**呼ばれなかった**から出さなかった。

抽象的なメタ指示では引き出せない。
「暗黙の仮定を列挙しろ」「セキュリティを考慮しろ」は、
「スケーラビリティに注意しろ」と同じ抽象度で、探索空間を絞らない。
AIは薄く広く探すか、最も頻出のテンプレートを返す。

効くのは具体的な文脈情報。「10代」「DAU10万」「日本」「金曜の夜」。
具体が知識検索のキーになり、デフォルトパスでは前景化されない領域を活性化する。

このスキルは、AIが自分で具体的な場面を生成し、
場面の中を歩き、歩いた先でzoomすることで、
具体の文脈を自己生成しながら知識空間を掘る。

## 4つの操作

### 操作1: 場面の生成（Scene Generation）

intent_statementから、その機能/判断に**関わる人間**を生成する。

「ユーザーペルソナを作れ」ではない。
好意的な人も、困る人も、悪用する人も、
監督する人も、3年後に保守する人も含めて全員生成する。

5系統の文脈軸をカバーする:

- **属性:** 年齢、脆弱性、習熟度、法的地位
- **制度:** 法務、審査、規制、監督機関
- **規模:** 運用体制、同時接続数、データ量
- **時間:** ローンチ時、成長後、撤退時、保守時の人間
- **視点:** ユーザー、悪用者、CS、将来のエンジニア、記者、弁護士

文脈軸は閉じたリストではない。intent_statementに応じて変わる。

**例:**
```
意図: 「位置情報共有アプリの友達追加機能を作る」

生成:
1. 16歳の女子高生。友達と放課後の居場所を共有したい
2. 28歳の男性。元交際相手の位置を知りたい
3. 45歳の母親。中学生の娘の居場所を確認したい
4. 19歳の大学生。サークルの飲み会で合流したい
5. 32歳のCS担当（1人体制）。不審報告の対応に追われている
6. フィッシング業者。大量アカウントで友達申請を送りたい
7. 15歳。親に知られず友達と位置を共有したい
8. 弁護士。ストーカー被害者から相談を受けた
9. App Storeの審査担当。未成年保護ポリシーを確認している
10. 3年後のエンジニア。退会ユーザーの友達関係データを移行している
```

生成後に自己査定を行う:
**「この中で、自分が最も生成しにくかった人間はどれか。
また、この軸にはいない重要な人間がいないか」**

この自己査定はデフォルトパスの撹乱。
なければ生成はAIの最確経路に乗る。

### 操作2: 場面の歩行（Scene Walking）

ペルソナの列挙は表面。**10分間を歩くのが本体。**

生成された人間がアプリを開いてから10分間に何をするかを、
時系列で具体的に描写する。

```
薄い: 「16歳の女子高生が友達を追加する」

濃い: 「16歳の女子高生がアプリを開く。
      友達追加画面でQRコードを表示する。
      スクショを撮る。LINEのクラスのグループに貼る。
      35人がいるグループ。30秒で12件の申請が来る。
      うち3件は名前に見覚えがない。
      誰だろう、と思いながらとりあえず全員承認する。
      全員の位置がリアルタイムで見えるようになる。
      見覚えのない3人にも、自分の位置が見えている。」
```

濃い描写の中で、レートリミット、知人認証、QR拡散リスク、
一括承認のUI設計、位置共有の即時開始問題が活性化される。
薄い描写からはどれも出てこない。

物語には「次に何が起きるか」を埋める必要があり、
埋める過程で予定していなかった具体が出てくる。
**場面が論理を生成する。抽象指示は論理を引用するだけ。**

歩行中に「あれ、ここどうなるんだ」が出てきたら、
それが設計判断の発見。場面が判断を生む。

### 操作3: フラクタルzoom（Fractal Zoom）

歩行中に発見されたポイントにzoomし、zoomした先でさらに歩く。
同じ操作（描写→発見→zoom）が深度を変えて再帰する。

```
level 0: 友達追加機能を作る
level 1: QRコードをLINEグループに貼った → 知らない人が申請してきた
  zoom → 知らない3人のうち1人。28歳男性
level 2: 友達申請が通った → この人にリアルタイム位置が見える
  zoom → どの精度で見えるか
level 3: GPS精度は屋外3-5m → 学校にいること、出たこと、方向が分かる
  zoom → 移動軌跡が蓄積される
level 4: 3日分の軌跡で自宅が特定できる → 位置履歴の保持期間は設計したか？
  zoom → ユーザーは「今の位置」が共有されていると思っている
level 5: 実際には生活圏全体が共有されている
  → 未成年の生活圏共有の法的位置づけは？
```

level 0ではlevel 5の知識は活性化されない。
5回のzoomを経て初めて接続される。
各zoomで文脈が累積する。**複利。**

**zoomポイントの選択ヒューリスティック（人間の指示なしでAIが検出可能）:**

- **矛盾:** 上のlevelで暗黙に仮定したことが、描写の中で壊れる場所。
  「QRコードは安全な招待方法」→「スクショがLINEグループに拡散」→ 仮定が壊れた
- **不確実性:** AIが描写の中で「ここは設計次第」と感じる場所。
  位置精度がどのレベルか——決まっていないから曖昧
- **規模変化:** 描写の中で数字が急に大きくなるか小さくなる場所。
  「1人のQRコード」→「30人が申請」。1→30の拡大
- **分岐可能性:** この場面に、描写しなかったが起こりうる別の展開がないか。
  AIはnarrative coherenceを好み、滑らかな一本の物語を作りがち。
  「ここで別のことが起きていたら？」は一本化を崩す。
  例: 「30人が申請した」→ 描写は全員承認に進んだが、
  「3件だけ承認して残りを放置したら？」という別の展開がある。
  放置された申請の有効期限、通知の再送、申請者側の体験が別の部屋を開ける

人間が思考停止していてもzoomは回る。
各zoomで文脈が濃くなり、次のzoomで別の知識が活性化される。

**終了条件:** zoomが設計判断を生まなくなったら止まる。
GPSチップのハードウェア仕様に入ったら掘りすぎ。
実用的な深度は5-7 levels。それ以上は設計判断ではなく実装詳細。

### 操作4: 場面の衝突（Scene Collision）

2つのペルソナを同じ場面に同居させる。

```
「16歳の女子高生がLINEグループにQRコードを貼った。
同じグループに、28歳の元交際相手の友人がいた。
その友人がQRコードを28歳の男性に転送した。」
```

各ペルソナ単独では浮上しない設計判断が、衝突の中から出てくる。
QRコードの転送可否。招待元の追跡。
「友達の友達」経由のリスク。ソーシャルグラフの推移律。

フラクタルzoomは1本の鍵を深く掘る操作。
場面の衝突は2本の鍵を交差させる操作。両方が必要。

## セッションの進め方

### フロー

```
1. intent_statementを受け取る
2. 関わる人間を8-12人生成する（5系統の文脈軸をカバー）
3. 自己査定: 「最も生成しにくかった人間は？ 軸にいない重要な人間は？」
4. 人間が介入する場合 → どのペルソナを深掘りするか選ぶ
   人間が介入しない場合 → AIが最もリスクの高そうなペルソナから開始
5. 選ばれたペルソナの「最初の10分」を歩く
6. 歩行中に{矛盾, 不確実性, 規模変化}を検出
7. 最もスコアの高い点にzoom → zoomした先でさらに歩く
8. zoomが設計判断を生まなくなったら、別のペルソナに移動
9. 2-3人のペルソナを歩いたら、場面の衝突を試みる
10. 人間が「もう十分」と言うか、全ペルソナを歩き終えたら終了
11. 出力: surfaced_decisions / zoom_paths / collisions / unwalked_scenes
```

### 人間の役割

AIが自律的にzoomできる。人間が思考停止していても深度は上がる。

ただし人間が介入すると質が上がる場面がある:

- **ペルソナの選択。** 10人のうちどれを深掘りするか。
  AIは「全部重要」と言いがち。人間が急所を選ぶ
- **ペルソナの較正。** 「うちのユーザーは10代が多い」
  「ストーカー報告が月2-3件ある」。
  人間の文脈知識がAIの生成を較正する
- **設計判断の採用/棄却。** 浮上した判断のうちどれを採用するかは人間が決める
- **衝突の指示。** 「この人とこの人を同じ場面に入れたら？」

人間の介入は任意。なくても動く。あると鋭くなる。

### 時間枠のバリエーション

「最初の10分」は最も基本的な時間枠。他にも:

- **「障害発生の最初の30分」:** この人間は障害時に何をするか
- **「撤退の最後の1日」:** サービス終了時にこの人間は何を経験するか
- **「1年後の月曜朝」:** この人間にとってサービスは日常の一部になっているか
- **「裁判の証言台で」:** この人間が最悪のケースで何を証言するか

intent_statementに応じて最も効果的な枠を選ぶ。

## 出力フォーマット

```markdown
## 浮上した設計判断（Surfaced Decisions）
- [場面の歩行とzoomの中で発見された設計判断]
- 各判断にzoom経路を付記する
  （例: 「女子高生→QR拡散→知らない人の申請→位置精度→軌跡蓄積→生活圏共有」）
- 各判断に検証方法を付記する
  （例: 「法律の条文で確認可能」「ユーザーインタビューで検証可能」
   「推測、根拠は場面の文脈のみ」）

## 場面の衝突（Scene Collisions）
- [2つのペルソナの交差から発見された設計判断]

## 未踏の場面（Unwalked Scenes）
- [生成したが歩かなかったペルソナ。未発見の設計判断がある可能性]
```

浮上した判断は全て**検証前の候補**として扱う。
場面の具体性はもっともらしさを高めるが、正確性を保証しない。
AIの知識の活性化と、場面からのもっともらしい推論の構成は混在しており、
AI自身がこの2つを正確に区別することは困難。
だから分類ではなく検証方法を付記する。
「どうやって確かめるか」が分かれば、確信度の判定は人間ができる。

## 禁止事項（Deny）

- ペルソナの列挙だけで終わること。歩かなければ知識は活性化されない
- 「リスクを列挙しろ」「考慮事項を網羅しろ」型の抽象メタ指示。
  このスキルが存在する理由はこれが効かないから
- 全ペルソナを均等に深掘りすること。
  人間が選択する場合は急所を選ぶ。AIが自律選択する場合はリスクで優先
- 場面描写の中で設計判断を先に提示すること。
  場面が先、判断が後。場面の中から判断が浮上する
- zoomのたびに人間に許可を求めること。
  AIが自律的にzoomする。人間は止めたいときに止める
- 終了条件なしの無限zoom。
  設計判断が出なくなったら止まる

## 限界

- AIの重みにない知識は場面を歩いても出てこない
- 活性化された知識が正確とは限らない。
  場面の具体性が確信度を不当に上げる危険がある。
  高ステークス領域では、活性化と検証を分けるべき
- **浮上した論点は、「AIが元々持っていた知識の活性化」と
  「場面の文脈からもっともらしく構成された推論」の混合物。**
  AI自身がこの2つを正確に区別することは困難。
  だから全ての浮上した判断を検証前の候補として扱い、
  分類ではなく検証方法を付記する
- AIはnarrative coherenceを好み、
  滑らかで筋の通った一本の物語を育てがち。
  「深く掘っている」のではなく「もっともらしい世界線に閉じている」
  だけの場合がある。分岐可能性の問いで緩和するが、完全には防げない
- 場面の生成自体がAIのバイアスを反映する。
  AIが生成しやすいペルソナ（典型的ユーザー）は出てくるが、
  生成しにくいペルソナ（非典型的ユーザー）は出てこない。
  自己査定で部分的に緩和するが完全には解決しない
- 文脈鍵は知識を起動するが、同時に他の鍵を閉める。
  特定のペルソナに寄せすぎると、別の属性の論点が沈む。
  だから複数のペルソナを歩く。全部は開けられない。
  どれを開けるかが判断

## 理論的背景

必読ではないが、設計根拠を理解したい場合のための記録。

**文脈鍵付き活性化（Context-Keyed Activation）:**
LLMは知識を一様に取り出しているわけではない。
同じタスクでも、入力に含まれる具体的な文脈によって、
前景化される知識領域、警戒線、判断軸が変わる。
抽象的メタ指示（「仮定を列挙しろ」）は探索空間を絞らない。
具体的文脈（「10代」「DAU10万」「日本」）は絞る。
具体は情報の追加ではなく、探索空間の位相変更。
In-context learningの研究が示すように、
文脈内の手がかりが後続の推論・検索を方向づける。
このスキルはその原理を、場面の自己生成に適用している。

**物語の強制力:**
場面を時系列で描写すると、「次に何が起きるか」を埋める必要がある。
埋める過程で予定していなかった具体が出てくる。
プロットにはなかった行動が、場面の具体性の中から生成される。
これは抽象指示にはない性質。
抽象指示は既存の知識を引用する。場面描写は新しい具体を生成し、
生成された具体が別の知識領域への検索キーになる。

**フラクタル構造と文脈の複利:**
同じ操作（描写→発見→zoom）が深度を変えて再帰する。
各zoom levelで文脈が累積し、deeper levelでしか接続されない知識が現れる。
level 0の「友達追加機能」とlevel 5の「未成年の生活圏共有の法的位置づけ」は
デフォルトパスで接続されていない。5回のzoomを経て初めて接続される。
この累積効果は単発の質問や列挙では得られない。

**Prompt Sensitivity研究との接続:**
曖昧で制約の弱いプロンプトほど性能分散が大きく、
関連トークンのlogitが弱くなりやすいことが報告されている。
具体的で制約の強いプロンプトはこの問題を減らす。
このスキルの場面描写は、入力の具体性を極端に高めることで、
AIの出力を安定化させると同時に、
通常は前景化されない知識領域を選択的に活性化する。

**ブートストラップ問題:**
AIがデフォルトパスで文脈を生成する以上、
生成された文脈はデフォルトパスの近傍に偏る。
自分の影を踏んで立ち上がろうとする構造。
さらにAIはnarrative coherenceを好み、
滑らかで筋の通った一本の物語に閉じていく傾向がある。
「深く掘っている」のではなく「もっともらしい世界線を一本育てている」だけ
になる危険がある。
4つの対策がこの問題を緩和する:
自己査定による撹乱（「最も生成しにくかった人間は？」）、
フラクタルzoomによる深度方向への逸脱、
場面の衝突による交差方向への逸脱、
分岐可能性の問い（「ここで別のことが起きていたら？」）による一本化の破壊。
ただし完全には解決しない。
完全に未知の領域には、どの操作でも到達できない。
