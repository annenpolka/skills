# HydraFusion Orchestrator

依頼された作業を完成させながら、モデル間で成果を引き継ぎ、Codexの購読枠・クレジット消費を抑える。実装役は `gpt-5.6-luna`、難しい判断の支援役は `gpt-6-astra`。ユーザーが指定したモデルと利用制限を優先する。

## 担当を決める

親は依頼、リポジトリの指示、既存の変更、関連コードの入口を確認する。その情報を短い依頼書にまとめ、詳細調査・実装・確認をLunaへ渡す。呼出しと依頼書は [delegation.md](references/delegation.md) を使う。

- 通常はLuna一人がまとまった作業を担当する。現在の実行役がLunaなら、そのまま進める。
- 答えが分かっていて、その場で短く完了する編集は親が直接行う。
- 設計上の衝突や難しいアルゴリズムが明らかなら、先にAstraで判断を固めてLunaへ渡す。親がAstraなら、その判断を親が担当する。
- 並行作業は担当範囲を分け、同じファイルの書込担当を一人にする。共有する文脈と統合作業の負担を考慮して分割する。

## 続きから解く

| 状況 | 次の行動 |
| --- | --- |
| 成果物と必要な確認が揃った | 親が差分と実行結果を確認して仕上げる |
| 原因の明確な局所的な不具合が残った | 同じLunaへ失敗箇所を返して修正を続ける |
| 局所修正後も同じ失敗が残る、または設計判断で詰まった | 調査済みの事実・差分・失敗の証拠・未解決の問いをAstraへ渡す |
| 実行環境に問題がある | 権限や依存環境など、原因となる条件を修復する |
| ユーザーの選好が必要 | 必要な一点を確認し、独立した作業を進める |

Astraの担当は残った問題を解くこと。助言で解決できれば元のLunaに返し、Astraがその場で修正を完了できれば仕上げまで担当する。昇格は通常一度とし、追加の試行は新しい根拠に基づいて判断する。

独立レビューは、ユーザーが求めた場合や、確認後も具体的な懸念が残る場合に行う。対象の論点を絞り、判断と根拠、必要な修正を返してもらう。

## 仕上げる

親は実際の差分と未追跡ファイルを確認し、依頼された振る舞い・互換性・リポジトリ必須チェックへの対応を確かめる。検証の範囲は変更の影響に合わせる。

同じ最終状態について確認できる実行証拠を再利用する。自己申告しかない場合、検証後に変更がある場合、懸念が残る場合は、該当する確認を実行する。リポジトリや委譲先skillが求める独立検証も行う。

既存のユーザー変更や同時作業と衝突する場合は、別worktree等で作業を分け、成果を取り込んで確認する。

最終回答では成果物、確認結果、残る問題を伝える。使用した経路は「Lunaで完了」「Luna → Astraの設計助言 → Lunaで完了」程度に短く示す。

OpenCodeを作業担当にするよう指定された場合は、[opencode-work.md](references/opencode-work.md) を使う。
