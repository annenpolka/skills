# Payments API v2.3（社内仕様・ドラフト）

最終更新: 2026-09-10 / オーナー: 決済基盤チーム

## 1. 目的

加盟店システムからの決済作成を、ネットワーク再送に対して安全にする。

## 2. POST /v1/payments

リクエストヘッダ:

- `Idempotency-Key`: 加盟店が生成する文字列。1つのキーは1回の決済作成意図に対応する。
- `Content-Type: application/json`

リクエストボディ:

- `amount`: 整数（最小通貨単位）
- `currency`: ISO 4217
- `merchant_order_id`: 加盟店側の注文ID

### 2.1 応答

| ステータス | 意味 |
|---|---|
| 201 | 決済を作成した。ボディに `payment_id` を含む |
| 400 | リクエスト不正（`amount` が 0 以下など） |
| 409 | 同じ `Idempotency-Key` のリクエストを処理中に再受信した |
| 422 | 与信不足 |

## 3. 再試行

- 加盟店は、5xx 応答またはタイムアウト時に、同じ `Idempotency-Key` で再試行してよい。
- 4xx 応答は再試行しない。

## 4. 冪等性

- 同じ `Idempotency-Key` のリクエストを再受信した場合、最初に処理した結果を返す。決済は一度だけ作成される。
- `Idempotency-Key` の保持期間はデプロイメント設定 `idempotency_retention_days` に従う。

## 5. 監査

- 決済作成の試行はすべて監査ログに記録する。
