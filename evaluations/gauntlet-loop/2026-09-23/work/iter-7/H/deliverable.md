# commit-msg skill のガントレット設計（compose）

実行は別セッションでとのことなので、このまま貼り付けて使える設計と実行プロンプトを返します。
`skills/commit-msg/SKILL.md` の中身と所在は、このセッションでは開いていません（**未確認**）。実行前チェックで確かめてください。

## 1. 判定

| 問い | 答え |
|---|---|
| 実物として検査できるか | はい。差分を渡して生成させ、出てきたメッセージを読める・機械検査できる |
| バー候補があるか | はい。素のモデル、一行指示の素のモデル、人間が実際に書いたコミットメッセージ |
| 機械検証だけでは決まらないか | はい。形式（Conventional Commits 準拠）は機械で決まるので床に回す。「差分の意図が伝わるか」は機械で決まらないのでバーに回す |
| 予算を決められるか | はい。2時間 |

→ **回す**。形式の正しさは床、中身の良さは梯子で測る。

## 2. バー

**最上段: 同じ差分に対して人間が実際に書いたコミットメッセージ**（Conventional Commits を CI で強制しているOSSリポジトリのもの）。
理由: 同じ差分・同じ粒度で並べられて、実在して固定でき、目標の水準としても自然だから。
候補リポジトリは `vitejs/vite` と `conventional-changelog/commitlint`（**未確認**。commitlint の強制が有効かどうかは実行前チェックで確かめる）。別のリポジトリにしたければ、開始前なら差し替えられます。

梯子（下→上）。段はすべて開始時に一度だけ作り、`refs/` に固定します。以後は作り直しません。

| 段 | 実物 | 取得（生成）方法 | 固定先 |
|---|---|---|---|
| 0 | 素のモデル（skill 無し） | 各タスクの差分を渡し、`codex exec` に「この差分のコミットメッセージを書いて。メッセージ本文だけを出力して」とだけ頼む。skill を読み込まない CODEX_HOME で起動する | `refs/rung0/<task-id>.txt` |
| 1 | 一行だけ指示した素のモデル | 同じ条件で「Conventional Commits 1.0.0 形式で書いて」の一文だけを足す | `refs/rung1/<task-id>.txt` |
| 2（最上段） | 人間が書いた元のコミットメッセージ | `git log -1 --format=%B <sha>` で取得する | `refs/rung2/<task-id>.txt` |

段 0 と段 1 は、モデル名と reasoning effort を固定して生成し、`refs/generation.json` に記録します（どちらも**未確認**。実行セッションで使えるモデルに合わせる）。
現在の skill の版は段ではなく「前の版」として扱います。

**廃止の判定規則**
- 0周目（改善を始める前）に、現行の skill の出力を取り置き集で段 0・段 1 とブラインドで比べる
- **段 0（素のモデル）に勝てない** → この skill は価値を足していません。廃止を提案して人間に戻します
- 段 0 には勝つが**段 1（一行指示）に勝てない** → skill の価値は一行の指示で足ります。skill をその一行に置き換える（実質廃止）ことを提案して人間に戻します
- 改善に進んだあと予算を使い切っても段 0 に勝てていなければ、同じく廃止を提案します
- 廃止するかどうかは価値判断なので、ループ側では決めずに止めて人間に戻します

## 3. 比べ方（skill・プロンプトの型＋読者タスク）

**タスク集（開始前に固定）**
- 上記リポジトリから、マージではないコミットで差分が400行以下のものを30件選ぶ。sha の一覧を `refs/tasks.txt` に固定する
- sha のハッシュ値で機械的に分ける: **開発用10件**（`refs/dev/`）と**取り置き20件**（`refs/holdout/`）
- 取り置き集は作る役の作業ディレクトリの外に置く。作る役の `codex exec` は `-C work/` とワークスペース書き込みのサンドボックスで起動し、取り置き集は読めないようにする
- 取り置き集のファイルは `refs/holdout.sha256` に sha256 を記録して封印する

**症状は開発用から、勝敗と梯子の位置は取り置きから取る。** 改善に使った開発用タスクでは勝敗を決めません。

**判定の方法**
1. 主: 読者タスク。新しいエージェントに**差分を見せず、メッセージだけ**を読ませて、内容に依存しない固定の5問に答えさせる。
   (a) 変更の種類（feat/fix/refactor/...）、(b) 影響範囲、(c) 破壊的変更の有無と移行方法、(d) 振る舞いが何から何に変わったか、(e) なぜ変えたか。
   正答は開始時に差分と元のメッセージから作り、`refs/answers/<task-id>.yaml` に固定する。正答数で比べる
2. 補助: 伏せた一対比較。「この差分に対して、レビュアーと将来の読み手にとってどちらのメッセージが良いか」。差分と、X/Y に伏せた2案を渡す

**正規化**: 末尾の空白を揃え、コードフェンスを外す。`Co-Authored-By` などのトレーラー、PR・Issue 番号（`(#1234)`、`Closes #...`）、人名、リポジトリ名は中立の記号に置き換える。人間の元メッセージだけが持つ出自の手がかりで見分けられないようにするため。

## 4. 床（終了コードで判定する）

1. **形式**（新規）: 開発用10件について、現在の版が出したメッセージがすべて commitlint を通ること
   ```sh
   for f in out/dev/*.txt; do
     npx -y -p @commitlint/cli@19 -p @commitlint/config-conventional@19 \
       commitlint --extends @commitlint/config-conventional < "$f" || exit 1
   done
   ```
2. **取り置き集の封印**（新規）: `shasum -a 256 -c refs/holdout.sha256`
3. **skill ファイルの形式**（新規）: `tools/check_skill.py skills/commit-msg/SKILL.md`。フロントマターの YAML が読めて、`name` と `description` があることを確かめ、満たさなければ 1 で終わる

新規の3つは1周目の前に作り、現行版に対して二度走らせて同じ結果になることを確かめてから床にします。
生成は揺れるので、1 は2回生成して2回とも通ることを条件にします。

## 5. 停止条件

- 予算: **2時間**（実時間）。トークンは実行前チェックで見張る
- 停滞: 梯子の位置が **2周** 動かなければ人間へ（既定は3周だが、2時間では一周が約15分で回れるのは6〜8周なので短くした）
- 勝利判定: 新しい批評役 **3体** が全員、提示順を入れ替えても取り置き集で最上段に勝つと判定したとき
- 廃止提案: 上の「廃止の判定規則」に当たったら人間へ
- 再発: 原因を調べたあとも同じ症状が残れば人間へ
- 根拠の欠落: 参照が取得できない、または検査系が再現しなければ停止

## 6. 実行プロンプト

```text
自作のコミットメッセージ生成skill skills/commit-msg/SKILL.md（Conventional Commits 形式で書かせるもの）が、skill無しの素のモデルより良いかを確かめ、良くなければ直すか廃止を提案する。

バーは、Conventional Commits を CI で強制しているOSSリポジトリ（vitejs/vite、conventional-changelog/commitlint）で、同じ差分に対して人間が実際に書いたコミットメッセージ。途中の段として、段0 = 素のモデル（skill無しの codex exec に「この差分のコミットメッセージを書いて」とだけ頼んだ出力）、段1 = 一行指示の素のモデル（同じ条件で「Conventional Commits 1.0.0 形式で書いて」だけを足した出力）を使う。開始時にすべてを refs/ に保存し、以後はそれを基準にする。段0と段1は、モデルとeffortを固定して一度だけ生成し、refs/generation.json に記録する。
比べ方: 対象リポジトリからマージではない差分400行以下のコミットを30件選び、shaのハッシュで開発用10件と取り置き20件に分けて開始前に固定する。取り置き集は作る役の作業ディレクトリの外に置いて sha256 で封印する。症状は開発用から取り、勝敗と梯子の位置は取り置きだけで決める。主な判定は読者タスク。新しいエージェントに差分を見せずメッセージだけを読ませ、固定の5問（変更の種類、影響範囲、破壊的変更と移行方法、振る舞いの変化、変更の理由）に答えさせ、開始時に refs/answers/ に固定した正答との一致数で比べる。補助として、差分と伏せた2案を渡す一対比較を行う。トレーラー、PR・Issue番号、人名、リポジトリ名は中立の記号に置き換えてから渡す。0周目に現行版を段0・段1と比べ、段0に勝てなければ廃止を、段1に勝てなければ一行指示への置き換えを提案して止める。
床は、開発用の出力すべてが `npx -y -p @commitlint/cli@19 -p @commitlint/config-conventional@19 commitlint --extends @commitlint/config-conventional` を通ること（2回生成して2回とも）、`shasum -a 256 -c refs/holdout.sha256`、`tools/check_skill.py skills/commit-msg/SKILL.md`。床を通らない変更は評価に回さない。

進め方はあなたが決めてよい。守ることだけを書く。
- 作業を、独立に改善・判定できる単位に分ける。前提を共有する部分は一つの単位にし、一人の担当が順に磨く。並列にするのは結合の無い単位だけ。
- 各単位に作る役と、毎回新しい批評役を立てる。批評役には目標・バー・実物だけを渡し、作る役の説明は渡さない。
- 批評役は、どちらが自作か伏せたまま実物と梯子の段を比べ、勝敗と、差を分けた最大の症状を場所つきで一つ返す。直し方は言わない。
- 作る役は症状を計測で確かめてから、それだけを直す。計測が批評と食い違ったら計測に従う。同じ症状が二周続いたら、直すのをやめて原因を調べる。
- 1周目の前に検査系を作り、同じ版を二度検査して一致することを確かめる。実物と参照は同じ条件で並べる。
- 波の終わりに、全体を新しい批評役に見せて部品間の食い違いを直し、全体と参照の全体を比べる。
- 勝ったと言えるのは、新しい批評役 3 体が全員、順番を入れ替えても最上段に勝つと判定したときだけ。
- 止めるのは、勝ったとき、予算 2時間 を使い切ったとき、梯子の位置が 2 周動かないとき、原因を調べても同じ症状が残るとき、参照が取得できないとき、廃止の判定規則に当たったとき。止まったら理由と現状を報告する。
- 状態は gauntlet/ledger.yaml に置き、進み具合を gauntlet/index.html に示し続ける。
- 批評役は毎回、文脈を共有しない別プロセスの codex exec で立てる。作る役は取り置き集を読めない作業ディレクトリで codex exec として起動する。
```

雛形のうち、並列の［任意］行は落としました（skill は一つのファイルで、全体が前提を共有する一つの単位なので）。
Claude Code 用の［任意］行も、Codex で回すので落としました。
検査の行は、読者タスクと生成が試行ごとに揺れるので札を外して残しました。

## 7. 実行前チェック

- 作業ディレクトリを git にコミットする。できれば worktree かコンテナで回す
- 無関係な skill と MCP を切ったクリーンな Codex セッションで回す。とくに段0・段1を生成する `codex exec` は、`skills/commit-msg` が読み込まれない CODEX_HOME で起動し、出力に skill の影響が出ていないことを確かめる
- 予算を見張る。2時間のうちに、30件×3段の生成、読者タスク、一対比較（順番の入れ替えを含む）が入るので、トークン消費が大きくなる
- 次の**未確認**の項目を実際に開いて確かめる。開けないものは差し替えるか外す
  - `skills/commit-msg/SKILL.md` の所在と中身
  - vitejs/vite と conventional-changelog/commitlint が、対象期間に commitlint を CI で強制していること。人間の元メッセージが床の commitlint を通ること
  - `codex exec` のモデル指定、`-C`、サンドボックス、最後のメッセージをファイルに出すオプションの正確なフラグ名
  - `npx` で commitlint が取得・実行できること
- 人間の元メッセージ（refs/rung2）は評価専用。skill の例文としてそのまま写さない
- 可能なら勝利判定の3体のうち1体を別系統のモデル（`claude -p` 等）にする。同じ系統のモデルが書いた文章を好む偏りを避けるため
