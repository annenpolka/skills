ガントレット・ループの設計（composeモード）から始めます。このセッションで実際に回すという指定がないので、ここではクリーンなセッションに貼り付ける実行プロンプトを組み立てます。今回はその手前の、参照（バー）を選ぶところで一度止まります。

## 1. 判定（Phase 0）

| 問い | 答え |
|---|---|
| 成果物を実物として検査できるか | はい。Next.jsのページをビルドして起動すれば、ヘッドレスブラウザで固定ビューポート（デスクトップ・モバイル）のスクリーンショットが撮れ、Lighthouseなどで計測もできる |
| 取得できるバーの候補があるか | はい。タスク管理アプリの公開ランディングページは多く、誰でも開いて撮影できる |
| 「良い」は機械検証だけでは決まらないか | 決まらない。伝わりやすさ、第一印象、信頼感は機械で判定できない。ビルド、a11y、表示性能などの機械で決まる部分は床に回す |
| 予算の上限を決められるか | はい。上限の数字（時間やトークン）は、バーが決まった後の停止条件の段で決めてもらいます |

→ **回します。**

## 2. バーの候補（ここで選んでください）

バーの指定がなかったので、まずバーを選びます。タスク管理アプリの実在ランディングページを候補に集め、六条件で絞りました。

**落とした候補**
- Notion（notion.com）: 同種同尺を満たさない。汎用ワークスペースの訴求で、タスク管理の見せ方とは比べられない
- Asana / Monday.com: 同種同尺を満たさない。企業向けの営業導線（デモ予約、導入企業ロゴの壁）が主役で、個人開発アプリとは内容の量も目的も違う
- Linear（linear.app）: 識別可能を満たさない。専用の3D・映像演出と開発規模の差が大きすぎ、比べても「規模が違う」以上の差が言葉にならない。そのうえチーム向けの開発ツールなので、同種とも言いにくい

**残した候補（いずれも公開URLを批評役が開いて撮影でき、開始時に `refs/` へスナップショットを固定できます）**

| 案 | 最上段 | 選ぶ理由（一文） |
|---|---|---|
| A | **Things 3**（culturedcode.com/things） | 少人数の開発元による個人向けタスク管理アプリで、立ち位置が近いまま、静かで完成度の高い見せ方の上限を示せる |
| B | **Todoist**（todoist.com） | 個人向けタスク管理の定番で、何ができるかをすぐ伝える見出しと導線の明快さで比べる基準としていちばん素直 |
| C | **Sunsama**（sunsama.com） | 「一日の計画」という切り口で差別化した個人向けタスク／計画アプリで、独自の価値の打ち出し方を磨きたいときに合う |

どれを選んでも、途中の段（梯子）には同じ個人向けタスク管理アプリの平均的なランディングページと評価の高いページを入れ、1周目の前にその順が崩れないか較正します。参照は水準の目安として並べるだけで、文言やデザインは成果物に写しません。

**A / B / C のどれにするか教えてください。** 選んでもらった後に、梯子の各段とその取得方法、比べ方、床のコマンド、停止条件（予算の上限を含む）、実行プロンプト、実行前チェックを書きます。
