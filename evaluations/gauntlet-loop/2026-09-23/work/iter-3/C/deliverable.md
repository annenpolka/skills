## 2. バー候補（ここで選んでください）

最上段（目標の水準）の候補です。個人向けタスク管理アプリの公開トップページを、六条件でふるいにかけました。

| 案 | 最上段の候補 | 理由（一文） |
|---|---|---|
| A | **Todoist**（https://todoist.com/ のトップページ） | 個人向けタスク管理というまったく同じカテゴリの定番で、何のアプリか、誰向けか、次に何を押せばよいかを1画面目で伝える水準として比べやすいです。 |
| B | **Things 3**（https://culturedcode.com/things/ ） | 個人開発に近い小さなチームが作る個人向けタスク管理アプリのLPで、機能を並べるのではなく、画面の見せ方と余白で質の高さを伝えています。 |
| C | **Sunsama**（https://www.sunsama.com/ のトップページ） | 同じ個人向けで、「日々の計画」という一つの切り口から価値を語り、フォーム登録まで導線を組み立てるLPの水準として比べられます。 |

候補から外したもの（六条件で落としました）:

- **Linear**（linear.app）: デザインの評価は非常に高いのですが、チーム向けの課題管理で、重いアニメーションを多用しています。個人向けのLPとは**同種同尺**で並べにくく、差が演出量の差になって**識別**しにくいので外しました。
- **Notion / Asana**: 製品の範囲が広く、企業向けの訴求が中心です。**同種同尺**を満たしません。
- 「おしゃれなSaaSのLP」「Awwwards受賞サイト」などの括り: **名指し**になっておらず、批評が一般論になるので使いません。

どの案でも共通の扱い:

- **素材ではない**: 参照は水準を測るものさしとしてだけ使います。文言、画像、レイアウトは成果物に写しません。批評役には「写しに見えるか」も毎回判定させます。
- **固定**: 開始時に、選んだ参照を固定ビューポートで撮影し、HTMLも一緒に `refs/` へ保存します。以後は実際のサイトが更新されても、保存した版を基準にします。
- 1行目のURLはトップページを想定しています。特定の下層ページ（例: 機能紹介ページ）を最上段にしたい場合は、開始前なら差し替えられます。

## 3. 比べ方の方針（バーによらず決まる部分）

- 領域はWeb/UIの型を使います。デスクトップ（例: 1440px幅）とモバイル（例: 390px幅）に固定し、同じ内容量で撮影します（1画面目と全体）。ブラインドの一対比較にします。
- LPの好みは判断が割れやすいので、比べる方法を**読者タスク**に変えて併用します。新しいエージェントに片方の1画面目だけを見せ、どちらでも同じ型の設問に答えさせます。「何の製品か」「誰向けか」「他と何が違うか」「次に何をすればよいか」の4問です。正答数で比べます。正答は開始時に作って `refs/` に固定します。
- 細かい条件（撮影の枚数、設問の正答、途中の段）は、バーが決まってから書きます。

## 4. 床の見込み（新規のものは1周目の前に作り、二度走らせて一致を確かめます）

- `next build` と `next lint`（または既存の lint コマンド）が通ること
- a11yの自動検査（axe、または Lighthouse の Accessibility）で違反がゼロ、または現行版から増えないこと（新規）
- 表示性能の予算: Lighthouse の Performance、LCP、CLS、JS転送量の上限（新規。値は現行版を計測してから決めます）
- 既存のテストがあればそれも床に入れます

## 5. 停止条件の既定値

- 停滞: 梯子の位置が3周動かなければ、あなたに戻します
- 勝利判定: 新しい批評役3体の全員一致で、しかも提示の順番を入れ替えても最上段に勝ったときだけ勝ちとします
- 予算: 下で伺います
- ほかに、参照が取得できなくなったとき、検査系が再現しないとき、次の一手にあなたの好みや判断が必要になったときも止めます
